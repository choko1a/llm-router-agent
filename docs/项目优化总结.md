# LLM Router Agent 项目优化总结

> 更新日期：2026-10-21。本文汇总当前工作副本中已完成并可从代码、测试或运行记录核对的改造。仓库没有可用的 Git 历史，因此文中的策略对比不等同于“当前版本与最初开源版本”的严格差异对比。

## 一、当前系统概览

项目已形成如下调用链：

```text
Streamlit UI / HTTP 客户端
        ↓
FastAPI：/health、/route、/chat
        ↓
路由器：rules / classifier / llm
        ↓
cheap 模型 → strong 模型 → agent 模型
                              ↓
                web_search / repo_analysis / code_assistant
```

`/route` 只返回路由判断，不调用负责回答的模型；`/chat` 根据最新用户消息判断路由，调用模型或 Agent，并返回回答及元数据。真实模型调用支持 OpenAI 和 OpenRouter 兼容接口；mock 模式可在没有有效模型密钥时演示流程。

## 二、已完成的完善与优化

### 1. 项目环境与运行方式

- 补充 Windows PowerShell 启动脚本：检查 Python、复用或重建不可用的 `.venv`、安装 `requirements.txt` 并运行 pytest；另有独立测试脚本，降低环境配置出错的概率。实现见 [`scripts/bootstrap_env.ps1`](../scripts/bootstrap_env.ps1) 和 [`scripts/run_tests.ps1`](../scripts/run_tests.ps1)。
- 在项目虚拟环境中补装真实搜索所需的 `tavily-python`；依赖已列在 [`requirements.txt`](../requirements.txt)。当前本机 `.venv` 的 `pyvenv.cfg` 表明它继承了 `choko` 环境的系统包，因此它不是完全隔离的虚拟环境；以后重建时以实际创建参数为准。
- 使用 `.env` 保存 API Key 等本地配置，提供 [`.env.example`](../.env.example) 作为模板。密钥不写入可由 UI 保存的运行时 JSON 配置。

### 2. FastAPI 接口与返回信息

- 梳理 `GET /health`、`POST /route`、`POST /chat` 的职责；`/route` 返回预测路由、置信度、原因、命中信号、预估成本与延迟以及后续回退路径。实现见 [`app/main.py`](../app/main.py) 和 [`app/models.py`](../app/models.py)。
- `/chat` 保留原有 `messages` 输入结构；响应在初始路由 `route_type` 之外，增加 `executed_route` 与 `fallback_history`，显示重试和升级后实际采用的路径。多工具调用时同时返回 `selected_tools`，原有 `selected_tool` 保留为最后一个工具。
- `estimated_cost_usd` 与 `estimated_latency_ms` 来自路由配置中的静态档位，只反映**初始路由的预估值**；`latency_ms` 才是本次接口请求的实际经过时间。静态预估值不是重试后实际产生的 API 账单。

### 3. 三种路由策略

- **规则路由：**依据搜索、代码、隐私、推理等信号及文本长度，选择 `cheap`、`strong` 或 `agent`。对较长且原本会进入 `cheap` 的请求进行升级。实现见 [`app/routing.py`](../app/routing.py) 和 [`app/routing_config.py`](../app/routing_config.py)。
- **分类器路由：**训练字符级 TF-IDF（`char_wb`，3–5 字符 n-gram）与 Logistic Regression，使用预测概率作为置信度。可通过 `ROUTER_MODE=classifier` 启用。实现见 [`scripts/train_router_classifier.py`](../scripts/train_router_classifier.py) 和 [`app/classifier_router.py`](../app/classifier_router.py)。
- **LLM-as-Router：**让路由模型返回结构化 JSON；校验路由类型与置信度，模型调用或解析失败时回退到规则路由。规则明确识别出工具请求时，避免 LLM 把它降到非 Agent 路径。实现见 [`app/llm_router.py`](../app/llm_router.py) 和 [`app/routing.py`](../app/routing.py)。

### 4. 真实模型、重试与逐级升级

- 对接 OpenAI 与 OpenRouter 兼容的 Chat Completions 接口；`cheap`、`strong`、`agent` 分别使用配置中的模型 ID。支持从 Streamlit 选择服务商和模型；运行时配置优先于 `.env` 中对应的模型 ID。实现见 [`app/providers/`](../app/providers/) 和 [`app/runtime_config.py`](../app/runtime_config.py)。
- 每次真实模型请求默认首次调用后最多重试 **2 次**（`MODEL_MAX_RETRIES=2`，即最多 3 次尝试），采用短暂递增等待。应用层最多允许配置 5 次额外重试，并关闭 OpenAI SDK 自带重试以免次数叠加。缺少 API Key 或模型配置属于不可恢复的配置错误，会立即报错。实现见 [`app/providers/retry.py`](../app/providers/retry.py)。
- 某一路径的模型请求在重试后仍失败，实际执行 `cheap → strong → agent`；Agent 是最后一级，失败则由 `/chat` 返回 HTTP 502。Agent 内部的每一轮模型请求单独重试，已经完成的工具不会因为后续模型请求重试而重复执行。实现见 [`app/llm_service.py`](../app/llm_service.py) 和 [`app/agents/agent_service.py`](../app/agents/agent_service.py)。
- LLM-as-Router 的模型请求也使用相同的重试机制；若仍失败，则使用规则路由。这属于**路由决策失败的回退**，与回答模型的逐级升级是两条不同流程。

### 5. Agent Tool Calling 与工具安全

- 将真实 API 模式中固定调用 `select_tool(query)` 一次的流程，改为把三个工具的定义交给支持 Tool Calling 的模型，并设置自动工具选择。模型可以直接答复，也可以请求工具；程序把 assistant 的工具调用消息和带对应 `tool_call_id` 的工具结果追加到本轮历史，再请模型判断下一步。默认最多执行 **3 次工具调用**，并关闭并行调用。实现见 [`app/agents/agent_service.py`](../app/agents/agent_service.py) 和 [`app/providers/tool_calling.py`](../app/providers/tool_calling.py)。
- 只允许通过明确的注册表调用 `web_search`、`repo_analysis`、`code_assistant`。工具参数必须是只含非空字符串 `query` 的 JSON 对象；未知工具、非法 JSON、缺参、类型错误和额外字段都会变为安全的工具错误结果。模型输出不会被当作 Python 代码执行，也不会作为任意文件路径传入工具。实现见 [`app/agents/tool_registry.py`](../app/agents/tool_registry.py)。
- mock 模式没有真实模型做工具决策，因此保留确定性工具选择，便于离线演示。`OPENROUTER_CODE_MODEL` 仍在旧配置中保留，但真实 Agent Tool Calling 统一使用 `OPENROUTER_AGENT_MODEL`。

### 6. 三类具体工具

- **`web_search`：**真实模式使用 Tavily 的 basic 搜索；缺少密钥、SDK、无效密钥、额度不足、超时与网络错误分别给出可识别的错误码，不把底层异常原文发送给模型。mock 模式明确标记结果为演示数据。当前本地 `.env` 中的 Tavily 密钥曾在真实请求中被 Tavily 判为无效，换成有效密钥并重启服务前，真实搜索仍不能成功。实现见 [`app/tools/web_search.py`](../app/tools/web_search.py)。
- **`repo_analysis`：**分析本地项目或公开 GitHub 仓库；对本地目录、README 读取长度和远端响应体设边界，忽略 `.env`、`.git`、虚拟环境、二进制文件等，并对常见密钥字符串做脱敏。实现见 [`app/tools/repo_analysis.py`](../app/tools/repo_analysis.py)。
- **`code_assistant`：**根据错误栈、测试、FastAPI 接口或配置请求生成静态分析与建议；它本身不运行 Python、shell、pytest 或用户生成的代码。旧 `code_debug` 导入保留兼容。实现见 [`app/tools/code_assistant.py`](../app/tools/code_assistant.py)。

### 7. Streamlit UI 与会话记忆

- 修复并完善聊天界面：可切换路由模式、mock/真实模式、服务商与模型 ID，查看所选路由、实际执行路由、回退历史、模型和工具元数据。运行时设置写入本地 JSON，且提供从 `.env` 重新载入模型 ID 的按钮。实现见 [`app_ui.py`](../app_ui.py)。
- 在当前 Streamlit 会话内保留最近的用户消息和模型回答，并在每次 `/chat` 请求中一并发送；默认最多保留 **6 轮**，超限时从最早的完整轮次开始移除。提供“清空对话”操作。该记忆仅存于当前 UI 会话，不跨浏览器会话持久化，也不保证单条超长消息的 token 上限。

### 8. 离线评测与自动测试

- 使用 JSONL 标注数据评测路由；脚本输出总体准确率、各路径准确率、混淆矩阵和“存在后续回退路径”的比例，可选择生成带时间戳的 JSON 报告。评测的是**路由选择**，目前没有测量真实 API 账单、回答质量或工具调用正确率。实现见 [`scripts/evaluate_router.py`](../scripts/evaluate_router.py)。
- pytest 覆盖接口、真实/模拟服务商分支、分类器、LLM 路由、UI 历史截断、工具参数验证、连续工具调用、重试与逐级升级、搜索故障分类等。最近一次完整运行结果：**84 passed**。

## 三、可复现的路由指标

使用项目内 [`data/eval_test_queries.jsonl`](../data/eval_test_queries.jsonl) 的 300 条标注测试样本，对比当前规则路由与已训练分类器；训练文件 [`data/eval_queries.jsonl`](../data/eval_queries.jsonl) 有 36 条样本，两份文件的查询文本没有完全相同的条目。

| 指标 | 规则路由 | 分类器路由 | 差异 |
|---|---:|---:|---:|
| 总体正确数 | 225 / 300 | 265 / 300 | 增加 40 条 |
| 总体准确率 | 75.0% | 88.3% | 提高 13.3 个百分点 |
| `strong` 类正确数 | 53 / 100 | 86 / 100 | 增加 33 条 |
| `strong` 请求误分到 `cheap` | 27 条 | 1 条 | 减少 26 条 |

这组数字说明**当前分类器策略相对当前规则策略**在这份项目内数据集上的表现；它不证明相对于最初开源版本的提升，也不能直接外推为线上准确率。尚未完成真实请求成本、实际 token 消耗、响应延迟和回答质量的前后对照测试，因此不应宣称这些指标提高了某个百分比。

## 四、当前边界与后续工作

1. 更换本地无效的 Tavily API Key 后，才能完成真实联网搜索的端到端验证；不要把密钥写入文档或提交仓库。
2. `fallback_policy` 在 `/route` 中只表示计划路径；模型真正的重试和升级发生在 `/chat`。初始路由的静态成本与延迟预估不包含升级后的额外模型请求。
3. UI 记忆只保留文本形式的用户和模型消息；Agent 单轮内部的工具调用历史不会跨独立 `/chat` 请求持久化。
4. 若要在简历中声称“成本降低”或“延迟减少”，需要使用同一批请求、同一批模型价格与实际 usage/耗时日志，对优化前后进行对照。当前仓库的 JSONL 评测不能提供这类结论。

## 五、常用运行命令

```powershell
# 安装依赖（已有 .venv 时）
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 完整测试
.\.venv\Scripts\python.exe -m pytest -q

# 启动 FastAPI（终端一）
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload

# 启动 Streamlit（终端二）
.\.venv\Scripts\python.exe -m streamlit run app_ui.py

# 离线评测
.\.venv\Scripts\python.exe scripts/evaluate_router.py --dataset data/eval_test_queries.jsonl
```

修改 `.env` 中的 API Key 或重试次数后，应重启 FastAPI。UI 保存的模型 ID 可能覆盖 `.env` 中对应的模型 ID；若希望重新采用 `.env` 的模型设置，可点击侧边栏的 **Load model IDs from .env**。
